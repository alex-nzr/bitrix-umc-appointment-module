# Модуль записи на приём для БИТ.УМЦ

Модуль предназначен для интеграции записи на приём между сайтом на Битриксе и БИТ.УМЦ.

## Что нужно для работы

Обмен с 1С выполняется через типовые веб-сервисы конфигурации. Для корректной работы необходимо:

- опубликовать базу 1С на веб-сервере;
- обеспечить доступ к опубликованной базе из внешних источников;
- указать корректные параметры подключения в настройках модуля.

## Что сделать после установки

После установки в административной панели Битрикса появится раздел `ANZ`.

Дальнейший порядок работы:

1. Открыть настройки модуля.
2. Заполнить доступы к базе 1С.
3. Проверить остальные параметры модуля.
4. При необходимости включить дополнительные опции и кастомизации.

Большинство настроек снабжены пояснениями и подсказками, поэтому базовую конфигурацию можно выполнить без изучения исходного кода.

## Требования

- БИТ.УМЦ: `2.1.24.9 (Corp)` или `2.0.48.15 (Prof)` и выше
- Битрикс: `25.0` и выше
- PHP: `8.1` и выше

## Архитектура модуля

Ниже приведена упрощённая схема движения данных:

```text
UMC
 │
 ▼
SDK
 │
 ▼
Integration (array -> DTO через Mapper) <-> CacheProvider
 │
 ▼
ExchangeService
 ├─ работа с Integration
 ├─ работа с репозиторием
 └─ orchestration бизнес-логики
 │
 ├─ Controller / Component
 ├─ Agent
 └─ Repository
    ├─ валидация
    ├─ CRUD
    └─ работа с моделями
       │
       ▼
     HL / ИБ / БД
```

### Как это читать

- `UMC` и `SDK` отвечают за внешний обмен с системой БИТ.УМЦ.
- `Integration` преобразует внешние данные в DTO и обратно.
- `CacheProvider` уменьшает количество повторных запросов к внешней системе.
- `ExchangeService` координирует обмен, работу с репозиториями и прикладную логику.
- `Controller` и `Component` отдают данные во внешний интерфейс.
- `Agent` используется для фоновых задач, например обновления данных.
- `Repository` и модели инкапсулируют работу с хранилищем.

## Когда смотреть исходный код

Имеет смысл переходить к коду, если нужно:

- изменить правила записи на приём;
- расширить обмен с 1С;
- добавить кастомную логику через события;
- доработать административную часть;
- изменить формат данных для фронтенда.
