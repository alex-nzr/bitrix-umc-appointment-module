# Архитектура

## Границы слоёв

Модуль использует Bitrix как runtime и инфраструктуру: контроллеры вызываются через стандартный AJAX-роутер, опции хранятся через `Bitrix\Main\Config\Option`, а локальные записи — через Bitrix ORM. Код модуля разделён по ответственности, а не по пользовательским экранам.

- `Controller\Appointment` принимает запрос, назначает prefilters и переводит ошибки в ответ Bitrix.
- `Service\Exchange\Manager` реализует прикладные операции: чтение справочников, бронирование слота, создание, отмену и обновление статуса записи.
- `Integration\UmcSdk` — единственная граница с SDK и SOAP 1С. `Gateway\Sdk` создаёт `BitUmcClient`, валидирует ответы, кеширует справочники и преобразует их в DTO.
- `Repository\UMC\AppointmentRepository` инкапсулирует доступ к `Model\RecordTable`.
- `Service\Security` проверяет данные и права до изменения записей или внешнего запроса.

`Service\Container` — сложившийся сервис-локатор модуля. Он создаёт и повторно использует `Manager`, `Sdk`, кеш, репозиторий и security-сервисы; новые зависимости подключаются через него, а не создаются в контроллере.

## Точки входа

| Файл | Роль |
| --- | --- |
| `include.php` | Подключает Composer autoload и запускает `Core\ServiceManager::includeModule()`. |
| `lib/Core/ServiceManager.php` | Регистрирует `Controller\Appointment`, подключает `main` и `iblock`, загружает UI-расширения. |
| `install/index.php` | Регистрирует модуль, таблицу, почтовые события, агенты, файлы и runtime-события. |
| `lib/Event/EventManager.php` | На `OnPageStart` добавляет пункты меню и автоподключение frontend-расширения на `OnProlog`. |

## Данные

Внешние структуры от SDK проходят `ResponseValidator`, затем `SdkResponseToDto` создаёт `ClinicDto`, `EmployeeDto`, `ServiceDto`, `ScheduleItemDto` и `TimeSlotDto`. Неизвестные поля сохраняются в `extra`, поэтому расширения 1С не теряются при передаче в контроллер.

Локальные записи хранятся в таблице `anz_appointment_record`, описанной `Model\RecordTable`. В ней есть UID записи 1С, данные клиники и врача, время визита, данные пациента, статус, комментарий и пользователь Битрикс. `AppointmentRepository` наследует общий репозиторий и требует непустой UID.

## Конфигурация и фоновые задачи

`Config\Configuration` определяет ID модуля по пути, кеширует значения `Option` в памяти запроса и предоставляет типизированные методы доступа. Она также определяет местоположение модуля, файлов журналов и demo-данных.

При установке регистрируются три агента:

- `Agent\Exchange::loadData()` — проверяет необходимость и запускает обновление данных;
- `Agent\Exchange::cleanLogFiles()` — удаляет устаревшие журналы согласно TTL;
- `Agent\Exchange::cleanModuleCache()` — очищает кеш интеграции.

Журналы хранятся в `{module_dir}/logs`; установщик создаёт там `.htaccess` с запретом доступа.
